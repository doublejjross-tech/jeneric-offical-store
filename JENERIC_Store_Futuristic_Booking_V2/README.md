# JENERIC Official Store — Discord Ticket Edition

## Included
- `public/index.html`: responsive storefront and interactive service selector
- `server.js`: Node.js backend, Discord OAuth sign-in, and private ticket channel creation
- `.env.example`: configuration template
- `render.yaml`: optional Render deployment blueprint

## Local setup
1. Install Node.js 20+.
2. Run `npm install`.
3. Copy `.env.example` to `.env` and fill in values.
4. Run `npm start` and visit http://localhost:3000.

## Configure Discord
1. In the Discord Developer Portal, create an application and add a bot. Enable the bot's **Server Members Intent only if needed for other features**; this app uses direct member fetch and does not require message content access.
2. Invite the bot to your server with **Manage Channels, View Channels, Send Messages, Read Message History, and Embed Links** permissions. Make sure its role is high enough to create channels under the chosen category.
3. Copy the Application/Client ID, OAuth Client Secret, Bot Token, Server/Guild ID, staff Role ID, and optional Ticket Category ID into `.env` or your host's secret environment variables. Never commit `.env` or share your bot token.
4. In the application's OAuth2 settings, add the **exact** redirect URL `https://YOUR-PUBLIC-DOMAIN/auth/callback` (or `http://localhost:3000/auth/callback` for local development).
5. Set `PUBLIC_URL` to the public HTTPS URL, with no trailing slash.
6. For customers to view their private tickets, they must already be members of your Discord server. Provide them a server invite separately. Staff role members can see every ticket.

## Public hosting
Deploy this entire folder as a **Node.js web service** (not static hosting), e.g. Render, Railway, or a VPS. Set the environment variables in the host dashboard. `npm start` launches the service and serves `public/index.html` automatically. Connect a domain in your host dashboard if desired. A public URL is provided by the host, not generated by the ZIP. Keep the service running for ticket creation.

## Security and limitations
- Discord OAuth authenticates the requesting customer; server secrets never enter browser code.
- Tickets are private Discord channels; access is restricted to the customer (when they are a server member), staff role, and bot. Discord administrators may still access channels.
- Rate limit: 3 requests per IP per hour. One open ticket per Discord account (based on cached channel topic). For large-scale production, replace the default in-memory session store and cache-based duplicate check with persistent storage.
- This is a **service request system**, not a payment processor. No payments are taken, no files are distributed automatically, and the only listed prices are Tweaking Utility Basic $30 / Extreme $45.
- Configure a verified payment provider and server-side checkout separately if you want actual purchases.
- When Discord settings are missing, the website is still viewable, but the Create Ticket button is disabled.

## V1.2 ticket questionnaire
Only Basic ($30), Advanced ($45), and PC Checkup appear in the store. After Discord sign-in and selecting one pack, a private ticket is created. The bot then asks the customer in the ticket for CPU, GPU, RAM type, RAM amount, RAM speed, motherboard, and main game. Each response has a 10-minute timeout; customers can type `skip`. The bot needs **Message Content Intent** enabled in the Discord Developer Portal > Bot > Privileged Gateway Intents, plus View Channels, Send Messages, Read Message History, and Manage Channels permissions. Customers must already belong to the Discord server. The optional DISCORD_STAFF_ROLE_ID controls staff visibility/mentions. For production, use a persistent session store instead of express-session's default MemoryStore.
